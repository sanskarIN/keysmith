# Development

## Shared commands

```bash
npm run dev          # frontend only
npm run tauri dev    # desktop app
npm run typecheck
npm run lint
npm run format:check
npm run version:check
npm run platform:check
npm test
npm run build

cargo fmt --all -- --check
cargo clippy -p keysmith-core --all-targets --all-features -- -D warnings
cargo test -p keysmith-core --all-features
cargo check -p keysmith --all-targets
cargo clippy -p keysmith --all-targets -- -D warnings
cargo test -p keysmith --lib
```

After recreating `src-tauri/gen/apple`, always run `npm run ios:prepare` again before building so `PrivacyInfo.xcprivacy` is restored.

## Rules

- Keep security-sensitive generation and policy logic in `keysmith-core` so Windows, macOS, Linux, Android, and iOS use the same audited implementation.
- Treat the TypeScript/webview-to-Tauri IPC boundary as untrusted input; UI constraints must be mirrored by Rust validation when they protect correctness, memory usage, secret handling, or policy meaning.
- Prefer official Tauri plugins that explicitly support the complete target set over direct platform-specific dependencies unless a reviewed abstraction is added for every platform.
- Do not restore the old direct `arboard` application dependency; clipboard text is routed through the cross-platform Tauri clipboard plugin.
- Native export must remain explicit and scoped to a user-selected save destination. Do not grant broad filesystem directories merely to simplify export code.
- Keep exact export readback verification. A write call returning success is not enough to tell the user that a mobile document provider preserved credential text.
- Do not log or intentionally persist generated secrets.
- Use best-effort zeroization for owned Rust secret buffers where practical, including error paths.
- Add typed validation at trust boundaries.
- Prefer pure functions and explicit state.
- Keep UI strings externalizable.
- Add a regression test for security, clipboard, export, mobile platform, release-integrity, or validation defects when practical.
- Add/document a manual platform smoke test when a behavior depends on an operating-system service and cannot be reliably unit tested.
- Update an ADR when changing foundational architecture/security decisions.
- Update `what_changed.md` with exact paths, verification evidence, limitations, and the next unfinished tasks before handing work off.

## Generated mobile projects

`src-tauri/gen/android` and `src-tauri/gen/apple` are generated by Tauri and ignored by Git. Do not hand-maintain or commit those generated IDE projects as the canonical source.

The reproducible inputs are:

- shared Rust/TypeScript source,
- `src-tauri/tauri.conf.json`,
- `src-tauri/tauri.android.conf.json`,
- `src-tauri/tauri.ios.conf.json`,
- Tauri/plugin dependencies,
- `src/assets/logo.svg`,
- `scripts/prepare-ios-privacy.mjs`,
- package scripts and CI.

## Adding a native/plugin capability

1. Confirm the capability is required by the product rather than convenience.
2. Confirm the implementation/plugin supports every native target that must retain the feature.
3. Add the narrowest permission identifiers to `src-tauri/capabilities/default.json`.
4. Add platform/configuration checks to `scripts/check-platforms.mjs` when the capability is release-critical.
5. Add automated and manual tests for desktop/mobile behavior.
6. Update `THREAT_MODEL.md`, `PRIVACY.md`, and architecture/release docs when trust boundaries change.

## Adding a generator option

1. Add the typed field in `crates/keysmith-core/src/policy.rs`.
2. Validate and implement it in the Rust core rather than relying only on HTML controls.
3. Add unit/property coverage for valid, invalid, boundary, and ambiguity-sensitive behavior.
4. Expose it through the existing narrow Tauri command types.
5. Add an accessible responsive control and actionable validation message.
6. Test both keyboard/desktop and touch/mobile layouts when the control changes UI geometry.
7. Update security/privacy/threat-model documentation if the data flow or trust boundary changes.

## Changing the application version

A release version is intentionally duplicated only in files required by the relevant ecosystems and visible UI. Update all of these together:

- `package.json`
- `Cargo.toml` under `[workspace.package]`
- `src-tauri/tauri.conf.json`
- visible semantic-version labels in `index.html`
- `CHANGELOG.md`
- release/handoff documentation as applicable

Then run:

```bash
npm run version:check
npm run platform:check
```

For a release candidate that will become `vX.Y.Z`, also validate the prospective tag by setting `KEYSMITH_EXPECTED_VERSION=vX.Y.Z` before running `npm run version:check`. The release workflow performs the same tag-to-manifest check automatically.

## Cross-platform completion rule

Do not call a change “fully cross-platform verified” until the exact candidate commit passes maintained Windows, macOS, Linux, Android, and iOS CI plus the platform smoke tests required by `docs/release.md`.
