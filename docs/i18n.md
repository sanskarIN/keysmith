# Internationalization

KeySmith ships English in `0.1.0`, but user-facing frontend copy is structured so additional locales can be added without rewriting application logic or moving locale concerns into the security-sensitive Rust core.

## Current structure

- `src/i18n/en.ts` is the canonical English catalog for static and runtime frontend copy.
- `src/i18n/index.ts` applies catalog strings to HTML elements marked with localization data attributes.
- `src/i18n/presets.ts` maps stable Rust preset identifiers to localized display names and descriptions while preserving the Rust/backend-provided fallback for future unknown preset IDs.
- `src/i18n/strength.ts` maps the stable zxcvbn score range to localized labels while preserving the backend label for an unknown future score.
- `src/i18n/*.test.ts` verifies translation application and fallback behavior.

The Rust core intentionally returns stable data and validation errors rather than depending on a frontend locale. Password-generation rules, randomness, entropy calculations, and security validation are locale-independent.

## Static copy

Static markup keeps readable English fallback text for development inspection and adds one of these attributes:

- `data-i18n="key"` for element text.
- `data-i18n-title="key"` for a `title` attribute.
- `data-i18n-aria-label="key"` for an accessible name.
- `data-i18n-placeholder="key"` for input placeholder text.

`applyTranslations()` replaces only known keys. Unknown keys keep their fallback markup instead of becoming blank.

## Runtime copy

Runtime status text must use the catalog or a small formatter such as `enFormat`. Do not add new user-facing sentences directly to event handlers when the same text belongs in the locale catalog.

This includes:

- generation success/failure,
- passphrase entropy status,
- clipboard success/failure,
- native export saved/cancelled/failure states,
- external-link opening failures,
- preset/loading state,
- theme/action labels.

Native Rust error strings remain English fallback detail in `0.1.0`. A future fully localized validation protocol should use stable structured error codes rather than translating generation/security logic in Rust.

Security-sensitive data must never be interpolated into translated diagnostic strings. In particular, never place generated passwords, passphrases, clipboard contents, batch values, private filesystem paths, tokens, or user credentials into logs/analytics/error telemetry. KeySmith currently has no analytics/telemetry system.

## Adding another locale

1. Add a locale catalog with the same keys as `en`.
2. Keep the catalog immutable and type-compatible with the English key set.
3. Add locale selection only as a non-secret preference.
4. Apply the selected catalog before interactive initialization.
5. Localize preset and strength helpers for the new locale.
6. Localize export/link/clipboard status copy without changing the native security operation.
7. Add tests for every new catalog and fallback path.
8. Manually review text expansion, 200% scaling, keyboard navigation, accessible names, native-dialog handoff text, and right-to-left layout if the language requires it.
9. Update `docs/accessibility.md`, privacy/help text, release notes, and screenshots when the shipped locale set changes.

## Translation quality rules

- Preserve security meaning; do not soften warnings about plaintext exports or clipboard exposure.
- Preserve the distinction between a saved export, a cancelled save dialog, and an actual write error.
- Keep product and protocol names such as KeySmith, Tauri, EFF Diceware, zxcvbn, and Apache-2.0 accurate.
- Prefer natural localized language over word-for-word translations.
- Do not translate generated secrets or the underlying EFF word list unless a separately reviewed word-list source and entropy model are introduced.
- Keep support addresses, repository URLs, legal identifiers, and exact external-link destinations unchanged.
- Do not expand an exact native URL allowlist merely to make translated link handling easier.
